# TongZip 项目开发说明书
**版本：V1.0｜需求基线与开发执行规范**

## 一、项目概述

### 1.1 项目名称
TongZip

### 1.2 产品定位
TongZip 是一款面向 Windows 用户的现代化桌面压缩软件，兼顾普通用户的操作便捷性与专业用户对格式兼容、安全性、批量处理、自动化和文件管理的需求。

产品以本地处理、数据安全、稳定可靠、免费使用为核心原则，逐步建立完整的压缩、解压、文件管理、任务调度和 Windows 系统集成能力。

### 1.3 产品目标
- 支持主流压缩格式的浏览、解压、创建及格式相关的高级操作。
- 提供稳定的任务管理、失败恢复和大文件处理能力。
- 深度集成 Windows 文件管理器、文件关联及右键菜单。
- 提供全文搜索、文档预览、智能解压和批量自动化能力。
- 建立安全、可测试、可升级、可维护的工程架构。
- 完全免费，不设置会员或付费功能。

### 1.4 目标用户
- 普通用户：日常压缩、解压、文件浏览和快速分享。
- 专业用户：大文件处理、加密、分卷、校验、批量操作和自动化。
- 高级用户：命令行、任务调度、归档管理和故障诊断。

## 二、当前项目状态

项目正在开发中，已有部分可运行功能。

已确认实现的功能：
1. 打开和浏览压缩包。
2. 创建压缩包。
3. 解压文件。
4. 压缩包内文件管理。
5. 任务中心。

上述功能属于当前已实现范围，但仍需通过代码检查和测试确认其完整程度、边界条件和稳定性。

当前压缩引擎方向为 7-Zip / 7z.dll。具体版本、调用方式、封装层、许可证、依赖关系和现有技术栈均需要通过项目源码确认，不得凭空推断。

首页和整体 UI 已经设计完成。后续开发应以现有设计为基准，不重新进行 UI 需求访谈；只有发现实际功能阻塞、可用性缺陷或技术限制时，才提出必要调整。

## 三、技术架构要求

### 3.1 平台与架构
- 支持 Windows 10 和 Windows 11。
- 支持 x64 和 ARM64 原生版本。
- 建立多架构自动构建、测试和发布流水线。
- 明确最低支持系统版本及安全维护范围。
- 在不同 Windows 版本和处理器架构上验证压缩引擎、原生 DLL、预览组件和安装程序的兼容性。

### 3.2 压缩引擎
以现有 7-Zip / 7z.dll 方案为基础，先检查项目代码，再决定是否需要升级、封装或调整。

要求：
- 统一压缩引擎调用接口。
- 将格式能力、错误处理和任务状态与 UI 解耦。
- 检查依赖版本、来源、许可证及安全漏洞。
- 统一管理引擎依赖与更新。
- 在条件允许时，将压缩引擎任务放入独立工作进程，避免引擎异常导致主程序退出。
- 在主程序和命令行工具之间复用核心业务逻辑。

### 3.3 内部模块化
采用职责清晰的内部模块设计，不开放第三方插件系统。

建议模块包括：
- 压缩引擎与格式能力管理。
- 文件系统与路径管理。
- 任务调度与后台执行。
- 安全校验与恶意归档防护。
- 文件预览与全文搜索。
- 归档内文件管理。
- 加密与密码管理。
- 配置、历史记录与本地数据管理。
- 日志、诊断与错误恢复。
- Windows 系统集成。
- 安装、更新与发布管理。

模块边界应便于独立测试、替换和维护。

## 四、压缩格式与归档能力

### 4.1 目标格式
至少评估并支持以下格式：

- ZIP
- 7Z
- RAR
- ISO
- TAR
- GZ
- BZ2
- XZ
- 其他可由现有引擎安全支持的格式

### 4.2 格式能力矩阵
必须针对每种格式分别识别以下能力：
- 打开与浏览。
- 解压。
- 创建。
- 加密与密码保护。
- 分卷创建与解压。
- 归档内文件增删改。
- 注释与附加信息读取。
- 元数据保留。
- 完整性测试和修复能力。

不得假定所有格式支持相同功能。

RAR 优先支持打开、浏览和解压。RAR 创建能力后续依据引擎能力、许可证及相关限制评估，不得承诺未验证的功能。

### 4.3 创建压缩包
同时提供简单模式与专业模式。

专业能力包括：
- 压缩等级。
- 格式选择。
- 密码和加密方式。
- 分卷大小。
- 文件名及目录结构设置。
- 元数据保留策略。
- 压缩预设。
- 创建后完整性验证。

### 4.4 归档内文件管理
支持能力允许的操作：
- 添加文件。
- 删除文件。
- 重命名。
- 复制和移动。
- 创建目录。
- 批量选择和批量操作。

执行修改前，应检测格式限制、归档锁定和数据风险。对于无法安全原位修改的格式，应采用临时归档、验证后替换等方案，并尽可能保留原始文件。

### 4.5 分卷管理
- 支持兼容格式的分卷创建和解压。
- 自动识别常见分卷命名规则。
- 检测缺卷、编号异常和文件顺序错误。
- 自动发现同目录下的相关分卷。
- 提供缺卷清单、定位建议和恢复建议。
- 对损坏分卷进行诊断，并明确说明恢复能力的边界。

### 4.6 自解压文件
- 尽可能安全读取兼容的自解压文件（SFX）。
- 不为浏览或解压而自动执行其中的可执行文件。
- 对不可信输入应用路径、资源和文件完整性检查。
- 无法安全识别时明确提示，不尝试运行文件。

## 五、加密、校验与数据可信度

### 5.1 专业加密
- 根据格式支持 ZIP AES、7z 加密等适用方案。
- 明确显示格式与加密方式的兼容性。
- 提示弱加密、兼容性限制及相关风险。
- 提供密码强度提示。
- 密码默认不以明文持久化。
- 使用 Windows 安全存储机制管理需要保存的密码。
- 普通日志中禁止记录密码。

### 5.2 完整校验体系
- 支持归档完整性测试。
- 支持格式相关的 CRC 校验。
- 支持常见哈希算法的计算与比对。
- 在任务中心展示校验结果。
- 支持批量校验，并为后续的校验清单导入导出预留扩展能力。
- 在适用场景下比较压缩前后文件内容。

必须明确：哈希值一致不代表文件来源可信；校验通过也不意味着文件没有恶意内容。

### 5.3 数字签名与来源验证
需求访谈已提出此项能力，但尚未完成选项确认。

后续应确定：
- 是否验证压缩包或相关文件的数字签名。
- 如何区分有效、无效、缺失和无法验证的签名。
- 是否需要可信发布者管理。
- 是否保留验证记录和审计信息。

任何未经验证的文件不得默认标记为可信。

## 六、安全体系

安全功能是发布前的必要条件，不应作为最后阶段才添加的附属功能。

### 6.1 恶意压缩包防护
- 防止路径穿越。
- 检测异常文件名与路径映射冲突。
- 控制符号链接和特殊文件处理。
- 防止意外覆盖重要文件。
- 检测压缩炸弹风险。
- 限制解压总量、文件数量、嵌套深度和资源消耗。
- 为异常归档提供可理解的错误说明。

### 6.2 权限管理
- 默认以普通用户权限运行。
- 操作前检查目标目录读写权限。
- 识别只读文件、文件占用和共享目录权限不足。
- 提供重试、跳过、另存路径等安全选项。
- 必要时才申请额外授权。
- 不绕过系统权限，不强行解除其他程序的文件占用。

### 6.3 文件操作事务
对关键操作采用尽可能可恢复的流程：
1. 预检源文件、目标目录和可用空间。
2. 在独立临时位置准备输出。
3. 执行压缩、解压或归档修改。
4. 检查输出内容与完整性。
5. 验证通过后安全替换目标文件。
6. 失败时尽可能恢复原状，并保留诊断记录。

不得在验证前破坏原始数据。

### 6.4 临时文件管理
- 按任务划分临时目录。
- 记录临时文件用途、所有者、创建时间和恢复状态。
- 启动时检查遗留临时文件。
- 设置空间预算与保留期限。
- 清理前确认文件不再被任务或恢复流程使用。

### 6.5 预览安全
- 限制预览文件大小、处理时间和资源消耗。
- 对复杂预览任务采用隔离工作进程。
- 禁止预览过程自动执行文档中的主动内容。
- 限制不必要的网络访问和路径访问。
- 预览失败时允许使用外部程序打开。

### 6.6 隐私
- 默认本地处理。
- 不主动上传用户文件内容。
- 不收集不必要的个人数据。
- 诊断日志发送前征得用户同意。
- 尽可能脱敏路径及其他敏感信息。
- 提供透明的诊断与遥测设置，并允许关闭非必要数据收集。

## 七、任务中心与后台执行

### 7.1 任务调度
支持：
- 多任务队列。
- 并行任务。
- 暂停、继续、取消和失败重试。
- 任务优先级。
- 并发数量与资源限制。
- 任务历史。
- 子任务状态。
- 详细日志与错误诊断。

### 7.2 中断恢复
- 持久化必要的任务状态。
- 应用重启后识别未完成任务。
- 提供继续、重试、重新打开或放弃等选择。
- 恢复前检查源文件、目标文件、临时文件和输出状态。
- 避免重复写入或错误覆盖。
- 不安全续传时应重新开始或提示用户处理。

### 7.3 长任务与系统事件
- 支持后台运行。
- 提供系统托盘和任务通知。
- 处理关机、注销和系统重启。
- 尽可能保存任务状态并恢复。
- 根据当前任务能否安全暂停，决定提醒、等待或安全终止。

### 7.4 磁盘空间管理
- 执行前估算空间需求。
- 任务执行过程中动态监控剩余空间。
- 空间不足时安全暂停或终止。
- 避免产生不完整输出冒充成功结果。

## 八、文件系统与路径兼容

### 8.1 网络磁盘与移动存储
- 支持网络共享、NAS、U 盘和移动硬盘。
- 检测断连、权限变化和读写失败。
- 断开时安全暂停任务。
- 连接恢复后重新校验文件状态。
- 提供继续或重试选项。
- 对无法安全续传的任务，提示重新开始。
- 不将离线缓存作为本阶段的必需功能。

### 8.2 超长路径与特殊字符
- 尽可能支持 Windows 长路径。
- 支持 Unicode 文件名、深层目录和特殊字符。
- 根据目标文件系统与压缩格式限制进行预检。
- 提供路径修复建议。
- 防止路径转换造成覆盖、重名或目录冲突。

### 8.3 元数据
- 尽可能保留修改时间、目录结构、只读和隐藏属性等信息。
- 根据格式能力和目标文件系统决定实际处理方式。
- 对无法保留的元数据采取明确的降级策略。
- 不得将未成功保留的元数据报告为已成功保留。

### 8.4 并发访问与外部修改
- 同一归档的并发读写必须受到协调。
- 实现锁所有权、超时与过期锁恢复机制。
- 使用 Windows 文件系统通知检测外部变化。
- 关键操作前重新校验文件状态。
- 必要时重新扫描，避免通知丢失导致缓存错误。
- 同步刷新视图、搜索索引和缓存。

## 九、重复文件与操作恢复

### 9.1 冲突检测
检测：
- 同名文件。
- 重复归档条目。
- 大小写冲突。
- 路径映射冲突。
- 重复目录。
- 不同文件路径映射到同一目标文件的情况。

### 9.2 冲突处理规则
支持：
- 覆盖。
- 跳过。
- 重命名。
- 保留较新文件。
- 应用到全部。
- 按任务保存默认策略。

在无法安全确定结果时暂停并询问用户。

### 9.3 文件内容比对
根据需要比较：
- 文件大小。
- 修改时间。
- 哈希值。
- 其他可用元数据。

不得仅凭文件名判断文件内容相同。

### 9.4 操作历史与撤销
- 为支持的文件操作记录必要的变更前后状态。
- 提供撤销与重做能力。
- 设定历史记录与备份空间上限。
- 明确标记不可撤销的操作。
- 删除、覆盖及合并操作应提供清晰的风险提示。

### 9.5 压缩包注释与附加信息
- 尽可能读取归档注释、文件注释及其他受支持的附加信息。
- 修改归档时尽可能保留原有信息。
- 对引擎或格式不支持的字段采取保守处理。
- 避免静默丢失可识别的附加信息。

## 十、搜索、预览与智能解压

### 10.1 全文搜索
- 支持文件名搜索。
- 支持适用格式中的文本内容搜索。
- 采用本地增量索引。
- 支持暂停、重建与清理索引。
- 设置资源限制。
- 显示搜索结果并支持定位到文件。
- 避免大型文件或大量归档导致资源失控。

### 10.2 文档预览
支持能力允许的：
- 图片。
- 文本。
- PDF。
- Office 文档。
- 代码文件。
- Markdown。

要求：
- 提供必要的搜索、缩放和内容查看能力。
- 不支持的格式可调用外部程序。
- 对大型文件设置资源限制。
- 采用安全隔离，禁止预览过程自动执行主动内容。

### 10.3 智能解压
采用规则引擎优先的方案，不依赖 AI 模型作为首发必要条件。

规则可以参考：
- 文件名。
- 目录结构。
- 文件类型。
- 重复文件情况。
- 归档内文件数量和结构特征。

目标是识别常见目录布局、推荐解压位置、检测重复文件并提供安全建议。

AI 的应用范围仅限智能解压方向，不扩展为通用 AI 助手。

## 十一、批量处理与命令行

### 11.1 批量处理
- 批量压缩、解压和校验。
- 统一输出路径。
- 支持命名规则。
- 支持冲突处理策略。
- 支持文件类型、名称和目录规则。
- 支持保存自动化预设。
- 在任务中心展示每个子任务的状态。

### 11.2 压缩预设
提供内置预设与自定义预设，例如：
- 快速压缩。
- 高压缩率。
- 兼容优先。
- 自定义参数组合。

### 11.3 命令行
支持：
- 压缩。
- 解压。
- 归档列表。
- 完整性测试。
- 校验与哈希计算。
- 批量处理。
- 标准退出码。
- 日志输出。

GUI 和 CLI 应尽可能共用核心引擎及业务逻辑，避免产生两套行为不一致的实现。

## 十二、Windows 系统集成

### 12.1 右键菜单
提供完整的文件管理器集成：
- 打开压缩包。
- 快速解压。
- 解压到指定目录。
- 创建压缩包。
- 添加到现有压缩包。

兼容 Windows 10 和 Windows 11 的不同菜单机制，并提供安装、修复和卸载管理。

### 12.2 文件关联
- 显示各格式的当前关联状态。
- 支持按格式设置关联。
- 检查与修复关联状态。
- 遵守 Windows 默认应用机制。
- 在修改系统关联前征得用户确认。

### 12.3 安装与卸载
- 支持安装路径选择。
- 支持文件关联和右键菜单配置。
- 支持快捷方式。
- 支持升级与修复。
- 卸载时允许用户选择是否保留个人数据。
- 避免卸载后残留不必要的系统集成项。

## 十三、本地数据与错误诊断

### 13.1 本地数据管理
保存：
- 设置。
- 最近打开记录。
- 任务历史。
- 自定义预设。
- 必要的恢复状态。
- 搜索索引及其管理信息。

要求：
- 支持清理历史。
- 支持设置保留期限。
- 支持数据导入导出。
- 规划升级迁移、备份及恢复。
- 敏感信息单独进行安全存储。

### 13.2 错误诊断
建立统一的错误分类、错误码和解决建议。

提供：
- 任务日志查看。
- 日志导出。
- 崩溃诊断。
- 任务恢复。
- 输出文件检查。
- 失败原因说明。

日志不得记录密码或不必要的敏感内容。

### 13.3 损坏归档恢复
提供独立诊断与恢复工作流：
- 检查归档结构。
- 分析损坏原因。
- 尝试恢复仍可读取的内容。
- 允许用户选择恢复范围。
- 输出到独立目录。
- 生成诊断报告。
- 尽可能保护原始归档。

必须明确说明：恢复能力取决于损坏类型和剩余数据，不能保证完整恢复。

## 十四、更新、测试与发布

### 14.1 更新
- 自动检查更新。
- 由用户确认安装。
- 验证更新包完整性和数字签名。
- 更新失败时保护原有可用版本。
- 启动检查失败时提供回滚能力。

### 14.2 自动化测试
建立单元测试、集成测试、格式兼容测试和回归测试体系。

覆盖：
- 各种压缩格式。
- 加密和错误密码。
- 损坏归档。
- 分卷与缺卷。
- 超大文件。
- 长路径。
- 网络断连。
- 磁盘空间不足。
- 权限不足。
- 文件占用。
- 任务暂停、取消与恢复。
- 并发访问。
- 更新失败和异常退出。
- 元数据保留与格式差异。

### 14.3 持续集成与发布
- 自动构建。
- 自动测试。
- 安装包验证。
- 依赖和许可证检查。
- 数字签名验证。
- 人工批准正式发布。
- 为 Windows x64 与 ARM64 分别生成并验证安装包。
- 建立稳定性门禁，测试不通过不得进入正式发布。

### 14.4 崩溃和引擎隔离
- 使用独立工作进程处理适合隔离的压缩任务。
- 崩溃后尽可能恢复任务状态。
- 检查已生成的输出文件。
- 不将未完成的输出标记为成功。
- 对重复执行有风险的操作进行恢复前校验。

## 十六、已确认的关键决策清单

1. 产品平台：Windows 桌面应用。
2. 系统支持：Windows 10 + Windows 11。
3. 处理器架构：x64 + ARM64 原生支持，并自动发布多架构版本。
4. 引擎方向：7-Zip / 7z.dll，具体实现以源码审计为准。
5. RAR：优先打开、浏览和解压，创建能力后续评估。
6. UI：已经设计完成，不重新开展 UI 需求访谈。
7. 入口：主界面、右键菜单和拖拽均需支持。
8. 解压：快速一键解压与自定义高级解压均需支持。
9. 创建压缩包：简单模式与专业模式兼顾。
10. 智能解压：规则引擎优先。
11. AI：只用于智能解压方向。
12. 安全：路径防护、资源限制、完整性验证、事务保护及恢复机制。
13. 隐私：默认本地处理，不主动上传用户文件。
14. 数据：本地保存，支持导入导出。
15. 价格：完全免费，无会员或付费功能。
16. 插件：不开放第三方插件系统。
17. 更新：自动检查，用户确认安装。
18. 网络存储：完整支持网络盘和移动存储，断连后安全恢复。
19. 路径：完整路径兼容，提供安全检测和修复建议。
20. 权限：最小权限、智能检测和安全重试。
21. 冲突：完整检测，支持可配置处理规则。
22. 元数据：尽可能完整保留，并识别格式能力。
23. 注释：完整读取，修改时尽可能保留。
24. 分卷：完整管理、自动发现缺卷、提供恢复建议。
25. SFX：安全读取，不自动执行。
26. 测试：建立完整自动化测试和持续集成。
27. 发布：正式发布流水线、稳定性门禁及更新回滚保护。

- 本地数据备份、迁移与恢复策略。

- 每个功能的实际完成度、测试覆盖率及验收标准。

## 十八、开发执行顺序

建议按以下顺序推进：

**第一步：项目盘点。** 获取现有源代码，检查技术栈、目录结构、已实现功能、依赖与许可证。

**第二步：建立基线。** 运行现有项目，建立自动化测试和当前功能清单，记录已知问题。

**第三步：完善核心与安全。** 优先处理压缩引擎封装、格式能力、错误诊断、恶意归档防护、事务保护和任务恢复。

**第四步：完善系统集成。** 实现或修复右键菜单、文件关联、安装升级及命令行功能。

**第五步：扩展专业能力。** 逐步开发搜索、预览、智能解压、批量自动化及高级校验。

**第六步：建立正式发布。** 完成 x64/ARM64 构建、兼容性测试、安全审查、安装包签名和更新回滚验证。

开发期间应持续测试，不应等到全部功能完成后再统一测试。

## 十九、最终验收原则

TongZip 的正式版本至少应满足：

- 已有核心功能稳定可用。
- 主要格式的支持范围经过验证并有明确说明。
- 危险文件操作具备安全保护。
- 任务失败、中断及恢复行为可预测、可诊断。
- 不会将未验证的输出标记为成功。
- Windows 10/11 和 x64/ARM64 的支持范围有实际测试依据。
- 安装、更新、卸载和文件关联行为可控。
- 关键功能具备自动化测试。
- 隐私策略透明，敏感数据受到保护。
- 不依赖尚未实现的功能来宣称产品已经达到完整能力。

**总原则：先确认现状，再建立可靠底座，逐步完善功能，最后以测试结果和明确的验收标准决定是否发布。**
