## 0. 验收原则（用户定档）

三态判定，不得笼统记"通过"：

| 状态 | 定义 |
|---|---|
| **已验证通过** | 有可追溯的自动化或人工测试证据（记录留痕） |
| **有条件接受** | 限制明确、不误导用户、无已知严重安全问题，且已写入发布说明 |
| **未验证** | 保留未完成状态，**不得在发布报告中计为通过** |

- **ARM64 红线**：当前打包配置仅 x64（package.json build.win 未声明 arm64 target）。在没有真实 ARM64 构建与兼容测试前，**产品宣传/发布说明/商店文案一律不得承诺原生 ARM64 支持**。
- 每项验证必须记录：`系统版本 / 测试条件 / 结果 / 复现步骤（失败时）/ 证据文件`，缺项不得归档。
- 冻结纪律：**不再新增功能、不扩大改动范围**；验收期间发现的缺陷按严重级进入"发布/带限制发布/定点修复"决策，不即时改码。
